point-in-time机制 as_of
============================================================

回测不只是查询过去的价格，还要还原当时能选择的证券和能使用的信息。
如果证券池来自今天，财报也取今天的最新版，即使价格区间完全正确，
仍可能得到当时无法实现的策略。point-in-time（PIT）机制让查询显式带上一个观察时点：
``as_of``\ ，即“截至这个时点，应该使用什么状态或版本”。

第一步：阻止未来信息进入决策
----------------------------------------------

财报的报告期与披露时间是两件事。2023 年年报属于 ``2023q4``\ ，
不代表 2023 年末就已经能看到；后续修订也不能提前进入历史决策。
下面是假设公司的净利润披露过程，金额单位为百万元：

.. list-table::
   :header-rows: 1

   * - 报告期
     - 披露日
     - 净利润
     - 版本
   * - 2023q4
     - 2024-04-20
     - 100
     - 首次披露
   * - 2023q4
     - 2025-04-20
     - 80
     - 后续修订

站在 2024-03-31，没有可用版本；站在 2024-06-30，只能使用 100；
查询最新修订版则得到 80。这里没有改变报告期，改变的是观察时点。
财务 PIT 先排除披露时间晚于 ``as_of`` 的记录，再在剩余记录中选择版本。
``statements="latest"`` 表示截止时点以内的最新版本，
``statements="all"`` 也只应包含截止时点以内可见的版本。

第二步：把后来消失的证券放回历史
----------------------------------------------

只使用今天仍然上市的股票回测过去，会把后来退市、合并或更名的对象漏掉，
产生幸存者偏差。反过来，今天存在的新股，也可能在回测时点尚未上市。

.. list-table::
   :header-rows: 1

   * - 假设证券
     - 2020 年
     - 今天
     - 2020 年证券池是否应包含
   * - A
     - 已上市
     - 已退市
     - 是
   * - B
     - 已上市
     - 仍上市
     - 是
   * - C
     - 尚未上市
     - 已上市
     - 否

从今天的 B、C 倒推历史，无法找回被遗漏的 A。
因此 PIT 必须从证券目录开始：按历史有效状态重建 A、B，
再查询它们当时可见的财报。证券代码同样有有效期；代码更名或复用时，
``instruments`` 需要结合 ``as_of`` 才能解析当时的对象。

as_of 的共同含义与具体边界
----------------------------------------------

``as_of`` 是查询的观察时点，而非一个通用的“数据日期”替身。
具体筛选哪条时间轴，由数据对象决定：

.. list-table::
   :header-rows: 1
   :widths: 28 38 34

   * - API
     - as_of 的作用
     - 其他时间参数
   * - ``all_instruments`` / ``instruments``
     - 还原该业务时点有效的证券状态与代码映射
     - 无需另传 date
   * - ``get_pit_financials_ex`` / ``get_factor``
     - 限制可使用的披露版本，避免使用后来的修订
     - start_quarter / end_quarter 选择报告期
   * - ``get_price``
     - 当前接口没有 as_of 参数
     - start_date / end_date 选择行情区间；adjust_orig 选择复权基准

证券层的业务有效时间，不等于数据库在那一天已收录什么。
上游证券模型通过不可变数据版本记录系统知识版本；严格复现还需固定数据版本。
当前指数的代码映射支持历史时点，但部分身份属性仍来自当前快照并按生命周期过滤，
不能把它当作所有指数属性的完整历史版本。

两类查询都省略 ``as_of`` 时，会使用各自的当前状态或最新版本。
这适合当前分析；回测应显式传入决策时点，并确认披露时间粒度与交易决策一致。
只有披露日期而没有日内时间时，不能据此假定开盘前已经获知当天所有公告。

在 libfinance 中使用
----------------------------------------------

首先重建证券池，再让财务查询使用同一决策时点。
下面示例只打印前三只证券以便阅读；实际证券池不应被 ``head(3)`` 截断：

.. code-block:: python

   import libfinance as lf

   as_of = "2024-06-28"
   universe = lf.all_instruments(type="CS", market="cn", as_of=as_of)
   print(universe[["order_book_id", "symbol", "listed_date"]].head(3))

   ids = universe["order_book_id"].head(3).tolist()
   for item in lf.instruments(ids, as_of=as_of):
       print(item.order_book_id, item.symbol, item.type)

   if ids:
       financials = lf.get_pit_financials_ex(
           ids, ["net_profit"], "2023q4", "2023q4",
           as_of=as_of, statements="latest",
       )
       print(financials)
       print(lf.get_factor(
           ids, ["net_profit_ttm"], "2024q1", "2024q1", as_of=as_of,
       ))

证券输出用于检查当时的身份，财务输出中的 ``info_date`` 用于核对披露时间。
没有记录可能意味着截止时点尚未披露，不能用今天的值补回，也不能直接当成零。
``get_factor`` 在这里查询财务衍生因子，与下一节的复权因子 exfactor 是不同概念。

比较财报版本时，只改变观察时点，保持代码、字段和报告期不变：

.. code-block:: python

   for cutoff in ("2024-03-31", "2024-06-30", None):
       print("as_of =", cutoff)
       print(lf.get_pit_financials_ex(
           "600000.XSHG", ["net_profit"], "2023q4", "2023q4",
           as_of=cutoff, statements="all",
       ))

这里打印的是服务端实际结果，不预设该公司的披露日期或修订金额。
前面的 100、80 只用于解释选择规则，不是这只股票的真实财报。

PIT 同时约束“选择谁”和“知道什么”，但不会代替完整的回测规则。
退市证券的最后可交易日、退市收益与持仓处置仍需正确处理；
仅把证券放回历史目录，还不足以保证回测完全消除幸存者偏差。
